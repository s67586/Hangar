Hangar 裝置牆

牆上的狀態是什麼意思

ready
adb 是 device，可以 build 也可以投影
agent_only
adb 進不去，但手機裡的 agent 還答得出話 —— 看得到、管不動
no_adb
連得到但 adb 不是 device，多半是手機重開機把 5555 弄丟了
unauthorized
這台 hub 還沒被那支手機授權過（要有人在手機上按「一律允許」）
unknown
只從掃描看到它，hangar list 那邊沒資料（那次輪詢多半失敗了）
offline
手機不在線上
unmanaged
掃得到但沒設定過。沒開偵錯的手機 adb 完全碰不到，所以只有 IP 與 MAC —— 機型與電量要等它裝上 agent

操作按鈕怎麼運作

先分清楚 hub 與這台電腦各自負責什麼，再看個別按鈕。

hub 只負責看

hub 不會動手機或改設定檔，也沒有這類端點。「立即更新」只是提早喚醒輪詢，仍然只跑原本兩個唯讀指令。

helper 才負責操作

投影、響鈴、註冊、更新 agent 與切換偵錯，都由按按鈕這台電腦上的 helper 執行。

先讓這台電腦能操作

  1. 執行 ./helper/hangar_helper.py --hub 這一頁的網址，再用瀏覽器開啟它印出的連結一次。
  2. 第一次投影某支手機前，在這台電腦跑一次 hangar setup；adb 授權綁定的是每台電腦自己的金鑰。

投影

視窗開在你自己這台電腦，不是 hub。hub 多半是沒人在看的常駐機器，把視窗開在那裡沒有幫助。

註冊與更新 agent

adb 是 device、但還沒有 agent 時，卡片會顯示「註冊 agent」，由 helper 透過該 profile 的 USB 或網路／Tailscale ADB 執行 hangar enroll -p <profile>。helper 不在時，卡片會提供可複製的指令。

agent 低於目前標準 0.1.2 時會顯示「更新agent」，執行 hangar enroll -p <profile> --reinstall。這需要 adb 是 device；就地升級不清資料，token 不會變，其他已入伍的電腦仍可使用。

手機已經入伍過、但這台電腦沒有它的 token（profile 重建過，或它是別台電腦入伍的）時，註冊會被手機端擋下來，卡片上會帶回 CLI 的提示：hangar enroll -p <profile> --takeover。接手會清掉手機上的入伍狀態，其他電腦手上的 token 一起失效 —— 那件事在這面牆上看不出來，所以它刻意沒有按鈕，要複製到終端機當面點頭。

響鈴

只用來識別仍能回應的手機。agent 沒回應、尚未入伍，或舊版沒有 can.ring 能力時，卡片會直接說明原因，不會留下按不動的按鈕。

偵錯

這是全手動狀態：按了才改變，不會定時自動恢復，避免在 QA 長測途中偷改測試條件。

偵錯關閉時，手機裡的 agent 是唯一能遠端重新開啟的路；agent 若失效，就必須有人拿著手機處理。
